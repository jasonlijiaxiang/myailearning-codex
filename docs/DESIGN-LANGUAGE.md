# 全站设计语言：雾灰青 A

这套语言服务于一个技术知识库，而不是营销落地页。页面要让读者感到清楚、从容、可信：先看见判断，再进入机制和证据；信息很多，但界面不催促。

## 1. 核心原则

1. **清醒，不冷硬**：以深灰蓝正文和白色页面为主，避免大面积高饱和蓝。
2. **留白组织信息**：优先用间距、细线和浅色区块分层，不靠层层卡片与重阴影。
3. **绿色只做强调**：黄绿色用于主要行动、阅读进度、当前状态和关键路径，不用于普通标签或大段背景。
4. **一页一套主节奏**：首页负责发现，目录页负责检索，模块页负责长文阅读，知识关系图负责探索；共享语言，不复制版式。
5. **正文永远优先**：装饰、英文小标题和数字标签不能抢过结论、机制、边界与来源。
6. **共享外壳必须可预测**：品牌、Header、Hero、阅读模式和目录属于全站组件，不得随模块色板、根字号或 CSS 加载顺序变化。

## 3. 字体与层级

- `--fb-font-editorial`：首页主标题、页面主标题、模块短标题和一句话定义，使用独立的中文宋体字栈，不引用模块可改写的 `--font-serif`。
- `--fb-font-ui`：正文、导航、按钮、筛选器和技术标签，使用无衬线字体，保持扫描效率。
- `--fb-font-code`：ID、计量标签、代码和结构编号；不用作连续正文。
- 大标题靠字号、字距和留白建立层级，不加渐变字、描边或装饰图标。
- 英文 kicker 只在确有导航价值时保留；它是元信息，不是每个区块的固定前缀。
- 正文目标字号为 `16–18px`，长文行高约 `1.7–1.8`，主要阅读宽度不超过 `820px`。

## 4. 布局与留白

- 全站宽容器上限使用 `--fb-shell-wide: 1480px`；常规页面容器使用 `--fb-shell: 1360px`，首页主要内容控制在约 `1248–1360px`。
- 页面首屏不做满屏封面。标题、定义和第一个有效入口应在笔记本首屏内出现。
- 大区块之间用 `52–84px` 的节奏；同一区块内部用 `16–32px`。
- 连续数据优先用“行”和细分隔线；只有需要独立理解或操作的内容才成为卡片。
- 圆角只用于完整区块和控件。表格行、目录行和连续步骤不逐项做悬浮卡片。
- 共享模块 Header 的导航高为 `60px`，Hero 主体桌面最小高为 `252px`；事实台账紧接 Hero，不用空白把内容推到第二屏。
- `980px` 以下事实台账降为两列，`720px` 以下 Header 使用单行品牌和 `44×44px` 菜单触控区，Hero 改为单列。

## 5. 共享组件规则

### 导航

- 白色或雾灰背景、细底线、低饱和文字。
- 当前动作通过文字、下划线或绿色短线表达，不使用蓝色胶囊。
- 移动端使用明确的折叠菜单，不按链接序号隐藏内容。
- 共享模块导航按 locale 使用同构入口：中文为“首页 / 本模块问答 / 来源 / 术语库 / English”，英文为“Home / Questions / Sources / Glossary / Chinese”；模块章节只进入模式目录，路径、文案与 ARIA 均由共享组件的静态 locale 契约提供。
- 默认导航文字使用 `--fb-chrome-muted`；Hover / Focus 切到 `--fb-chrome-link`，同时出现绿色短线或可见焦点环。
- 品牌、桌面导航和移动菜单必须由 `UnifiedModuleScaffold` 内的 `UnifiedModuleHero` 输出，模块不得复制或删减入口。

### Hero

- 首页：一句主张、一个解释、最多两个主要入口，再补一组阅读方式。
- 目录页：标题、用途、规模概览和第一个搜索入口。
- 模块页：模块名、定义、适用位置与少量指标；不使用深色大封面。
- 共享模块 Hero 的信息顺序固定为：短标题 → 当前语言模块名 → 一句话定义 → 责任定位 → 阅读规模 → 四项核心判断。中文页可并列英文副题并标注 `lang="en"`；英文页只显示英文身份，不强制重复中文。固定的是阅读语法，不是每个模块的正文构图。
- 每个文字角色必须直接声明 `color`、字号、字重与行高；不能靠模块根节点继承，也不能靠样式文件的加载顺序碰巧一致。

### 搜索与筛选

- 搜索框是一个完整控件，边框清楚，标签始终可见。
- 筛选项默认低调，选中态用深文字或浅绿底；蓝色不承担选中态。
- Sticky 只在长目录确实受益时使用，不叠加重阴影和大面积模糊。

### 卡片、列表与表格

- 目录结果使用开放列表：白底、细线、清楚的标题和摘要。
- 卡片阴影只表达“可浮起的操作层”，普通知识卡不使用阴影。
- 表头使用雾灰底和较小字重；正文保持足够字号，不用密集微型文本。
- 保留原生表格时必须提供 `caption`、列头与行头 `scope`；横向滚动容器使用有名称、可聚焦的 `region`，让键盘用户能到达最右列。

### 重要边界

- 轻量判断使用绿色左线或浅绿底。
- 可能导致过度承诺、错误架构或安全问题的边界使用砖红色及文字标签。
- 不能只靠颜色区分普通说明与重要边界。

### 焦点与动效

- 所有链接、按钮、输入和 `summary` 都必须有清晰的 `:focus-visible`。
- 动效只说明状态变化，时长短，不造成布局位移；遵守 `prefers-reduced-motion`。

## 6. 组件边界与级联所有权

| 层级 | 唯一所有者 | 可以做 | 不可以做 |
| --- | --- | --- | --- |
| 全站基础 Token | `app/globals.css` | 定义 `--fb-*`、字体、间距、圆角、动效 | 在模块 CSS 再建 `:root` 或覆盖 `--fb-chrome-*` |
| 共享 Header / Hero | `UnifiedModuleScaffold` + `UnifiedModuleHero` + `unified-module-reader.module.css` | 使用 `--fb-chrome-*`，完整声明每个文字角色 | 模块用 `.page a`、`.page h1`、裸 `header/nav` 改变它的颜色或字体 |
| 阅读任务与目录 | `DenseModuleReadingModes` + 共享样式 | 统一模式语义、Hash、键盘和移动入口；保留浏览器 state，展开折叠深链并在响应式重排后复核定位 | 模块复制 Tab、目录控制器或另建一套移动导航 |
| 英文内容分区 | `EnglishModulePage` 的共享 section renderer | 每个 section 用可见 H2 的稳定 ID 提供 accessible name | 只依赖视觉标题，或为单一模块另加隐藏标题和私有 ID |
| 模块正文 | 模块组件与局部 CSS Module | 定义 `--mcp-*`、`--a2a-*` 等内容语义色，设计独有机制图 | 穿透 `[data-module-hero="unified"]`，或用 `!important` 抢共享外壳 |

CSS Module 只会哈希类名，不会阻止 `.page a` 命中后代。`UnifiedModuleScaffold` 因此把 Header / Hero 放在模块正文根之前，两者是兄弟节点；`.page`、`.reader` 等模块选择器只包住正文。共享样式再为每个文字角色直接指定颜色、字体、字号、字重、行高和字距。级联顺序不再参与模块间的一致性判断。

共享 `brief` 路由通过不可变的模块配置显式接入统一 reader；当前已接入 Solution Patterns、Model Landscape、Multimodal、VeADK、AgentKit、Evaluation、AI Governance、Security、AI Gateway、AI Ops、Predictive AI / MLOps、LLM、Fine-tuning、LLM Training 与 Data Engineering，专用 LLM Inference、Prompt Engineering 与 AI Agent / MCP / A2A 也复用同一阅读任务和页面外壳。配置只声明 Hero 决策事实、目录和 authored group 映射，正文、稳定锚点、独有机制视图与来源仍由各模块内容 owner 维护。专用 Primer 若已呈现生产边界，必须通过组件契约把所有权交给共享 reader，不能让同一边界重复出现；历史知识视图值或交互选择值若曾作为公开 Hash，必须由 route-local、唯一的真实 DOM 锚点承接，并让 Back / Forward 同步恢复对应界面状态。新增批次不得在路由里累积 slug 分支，也不得增加模块专属 Header、Tab 或 CSS 补丁。

## 7. 页面家族的应用

- **首页**：最开放、留白最多，用浅色引导线连接场景、问题、时间路径和术语。同级入口统一容器宽度、标题层级、引导线与圆点；内部可按任务分别使用路径、检索或时间卡片。
- **模块页**：使用紧凑 Hero、阅读侧栏和白色正文面；机制图可以有自己的语义色，但消费全站 token。
- **问题、术语、来源目录**：搜索优先，以行式结果替代彩色卡片墙。
- **Coding Agent 选型页**：沿用目录页语法，突出筛选条件、事实日期和适用边界。
- **动态知识关系图**：保留深色工作台以支持空间关系，但把荧光蓝降为雾灰青，外壳、文字和绿色强调与全站一致。
- **英文页**：共享同一 token、组件层级和响应式规则；英文文案长度不得通过缩小字号解决。

## 8. 禁止项

- 不新增高饱和蓝作为默认强调色。
- 不为每个模块写 slug 或固定卡片数量的 CSS 特判。
- 不用“渐变 + 大阴影 + 多层圆角卡”制造层级。
- 不把维护状态、构建信息或视觉规范展示给读者。
- 不为排版凑卡片、图表或固定列数；数量变化时仍需保持可读。
- 不在模块 CSS 声明 `--fb-chrome-*`，不从模块根节点重置所有 `a / h1 / header / nav` 的字体颜色。
- 不在共享 Header / Hero 使用 `inherit`、`currentColor` 或 `!important` 作为最终文字色；每个角色直接消费语义 Token。
- 不依赖 CSS 注入顺序解决冲突；如果交换两个样式文件的加载顺序会变色，说明组件边界仍未完成。

## 9. 自动门禁与回归检查

- `tests/design-language-contract.test.mjs` 校验 Token 唯一所有者、全部文字角色的颜色与排版、Hover / Focus / 移动菜单状态，以及 Header 与模块正文的兄弟节点边界。
- 共享视觉发生变化时，至少复核中文首页、英文首页、一个 shared 模块、一个 dedicated 模块、问题目录、术语目录、来源页、Coding Agent 页和中英文知识关系图。
- Header / Hero 变化必须并排检查所有已接入 `UnifiedModuleHero` 的正式模块；在 `1440×900`、约 `1024px` 和 `390px` 分别比较品牌、导航、短标题、中英文副题、定义、定位、指标和事实台账的计算色值、字号、字重与行高。
- 交互复核覆盖 Hover、键盘 Focus、移动菜单开合、Hash 深链、Back、模式切换和目录当前位置；同时检查页面无全局横向溢出。
- 自动结构测试只能阻止已知回归，不能替代真实内容的视觉复核。任何新的系统性问题都要同时更新共享实现、本文件、质量追溯矩阵和可自动化门禁。
