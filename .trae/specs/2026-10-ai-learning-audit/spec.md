# AI 学习知识库：身份重建、知识复核与设计修整 — 需求规格

## Overview

- **Summary**：把现有的「云计算 × AI 平台售前知识库」改造为**个人 AI 学习库**：以模块为主线、以场景为切入，支持由浅入深学习；同时完成一轮知识真实性/可靠性/时效性复核，并在保留现有视觉风格的前提下定向修整设计、清理臃肿 CSS。
- **Purpose**：项目所有者（唯一主要使用者）用它系统学习 AI 的各个模块与场景；项目此前用 Codex 开发，现转为跨 Agent Tools 协作，需要一次全面审视作为新基线。
- **Target Users**：项目所有者本人——具备 Python / API 基础，按「模块 + 场景」组织学习，需要高知识密度、高可读性、强实用性、无 AI 腔的中文内容。

## Goals

- G1：全站身份从「售前/客户现场」转为「个人学习」视角（品牌、标题、结构性字段标签）。
- G2：知识内容保持现有高可靠基线，并对时效性最强的模块做定向复核补漏。
- G3：在知识密度不下降的前提下，进一步提高可读性与实用性，去除 AI 腔。
- G4：保留「雾灰青 + 柠檬绿 + 宋体编辑风」的辨识度，定向修正排版/层级问题，并显著精简 CSS。
- G5：冻结英文建设，所有改动只面向中文页面，且不破坏现有英文结构门禁。

## Non-Goals

- N1：不撰写、不扩写任何英文正文；不删除历史英文内容（仅冻结）。
- N2：不做整站信息架构重排与路由重命名；27 个模块的 slug、稳定锚点、问答 ID 保持不变。
- N3：不更换技术栈（Next.js 16 / React 19 / vinext / Cloudflare）。
- N4：不引入登录、个人会话、远程数据源或新的运行时依赖。
- N5：不重写知识正文的技术实质；场景叙事中的「客户/现场」等教学情境不做机械清除。
- N6：不执行 portable 打包、handoff 审计、批次打磨 seal 等按需流程。

## Background & Context

- 规模：27 个已发布模块（10 个知识层；其中 4 个场景模块）、396 道问答、181 个术语、313 条来源。
- 内容契约成熟：一切从 `app/modules/<slug>/manifest.mjs` 派生；`module-publication.mjs`、`module-content-registry.mjs`、`knowledge-map.mjs`、术语、Reference 均单一数据源。
- 时效性机制：来源按 kind 设 30/90/180 天复核周期；`npm run sources:report` 实测 **0 条过期**（104 条 30 天内到期，属 7 月底批量核验后的正常节奏）。
- 自动化现状：`npm run check:fast` 全绿（lint、typecheck、33 项单测）；`npm run check` 另含双语结构检查、生产构建、bundle 预算、98 项渲染/设计检查。
- 独立抽查：OpenAI Sora 2 / Videos API「2026-03-24 公告、2026-09-24 停服」与官方页面一致，台账日期角色准确。
- 已确认问题：
  1. 身份错配——「售前」101 处/32 文件、「客户」641 处、Presales/Fieldbook 187 处；
  2. 模块页 H1 语义倒置——「LLM」等缩写以 58–78px 巨型字号作 H1，完整中文名反而作小字；
  3. CSS 臃肿——全站 12 个 CSS 文件共 14,260 行（去重口径），其中 `fieldbook-v3.css` 8,771 行，含大量被覆盖的无消费者旧样式；
  4. 首屏与间距存在封面化残留（部分旧 `.hero` 92vh/深色样式被覆盖但仍保留）。
- 用户已确认方向（2026-10-03）：① 全面改为学习库定位；② 保留风格、定向修整；③ 知识复核补漏与设计修整并行；④ 英文冻结、只维护中文。

## Functional Requirements

- **FR-1（身份）**：中文页面的站点标题、品牌字样、页头页脚、Hero 身份表述全部改为学习库定位，不再以「售前知识库 / Presales Fieldbook」自称。
- **FR-2（字段语言）**：结构性标签与字段名改为学习者视角，例如「客户问题 → 学习问答 / 问答」、「售前下一问 → 追问 / 自测」、「客户实战包 → 实战练习」、「现场查证 → 查证」等；具体映射按语境确定，不做逐词机械替换。
- **FR-3（内容保留）**：396 道问答、27 个模块正文、4 个场景的教学叙事与 worked example 全部保留；其中作为**叙事角色**出现的「客户说/某客户场景」可自然保留或改写，但不得改变技术结论、数字、边界与证据。
- **FR-4（知识复核）**：对高时效对象逐条对照一手来源复核并留痕：模型目录与格局（OpenAI/Anthropic/Google 当期家族）、视频生成（Veo 当期状态、Sora 停服）、MCP/A2A 协议细节、LLM Inference 容量口径；错误全部修正。
- **FR-5（标题层级）**：模块页 H1 以完整中文模块名为第一语义，缩写名与英文名为副信息；保留大号编辑级标题的视觉表现力，但纠正「缩写主视觉、全名小字」的倒置。
- **FR-6（CSS 精简）**：删除无消费者的死样式与重复覆盖，显著缩减 CSS 体积；视觉表现以「像素级无回归」为约束（除 FR-5 有意修改处）。
- **FR-7（可读性）**：首屏即见真实知识入口与判断；连续正文、问答、表格维持字号/行高/行宽标准；重要边界不折叠。
- **FR-8（实用性）**：学习目标、自测追问、实战任务（含产物与通过标准）、搜索与深链在中文页面完整可达。
- **FR-9（英文冻结）**：改动不触及英文正文与英文路由的可见行为；双语结构检查继续通过。

## Non-Functional Requirements

- **NFR-1（知识密度）**：每屏有效信息量不下降；删除的只允许是重复、空泛或被覆盖的内容，不得为排版删概念、边界或证据。
- **NFR-2（去 AI 腔）**：具体名词、日常动词、有判断与边界；无口号、无空话、无套路句式（「不是 A 而是 B」「首先其次最后」等不被重复套用）。
- **NFR-3（可靠性）**：每条可变事实可经稳定 sourceId 追溯，证据等级、核验日期、外推边界齐备。
- **NFR-4（视觉与可访问性）**：浅/深色模式、键盘、焦点、无脚本 SSR、reduced-motion 行为不破坏；无全局横向溢出。
- **NFR-5（可验证）**：所有变更受现有自动化门禁与定向回归保护；视觉修整用真实浏览器（Chrome）人工复核。

## Constraints

- **Technical**：Node ≥ 22.13；仅可用现有依赖；遵循 `AGENTS.md` 与 `docs/` 下构建/质量标准；共享所有者文件（publication、registry、terminology、reference-content）单写者串行修改。
- **Business**：本轮只做中文版；未经明确要求不触发 Sites 发布之外的流程；正式发布仍走 `main` 精确提交门禁。
- **Dependencies**：视觉 QA 依赖真实 Chrome（external chrome 能力或用户本机浏览器）；内置浏览器截图在当前环境不可用。

## Assumptions

- A1：现有内容经多轮审查，技术实质总体可靠；本轮以「定向复核 + 补漏」而非「逐句重写」为原则。
- A2：学习库定位下，保留「真实场景问答」这一高效学习形式，仅改身份层语言；这也是用户选择「内容实质保留」的含义。
- A3：CSS 死代码可通过静态引用分析 + 浏览器渲染比对安全识别。

## Acceptance Criteria

### AC-1：读者可见的学习库身份
- **Type** `rule`
- **Given** 任一中文页面（首页 / 模块 / 问答 / 术语 / 来源 / 图谱）
- **When** 读者浏览品牌、标题、Hero、页头页脚与结构性字段标签
- **Then** 不出现「售前知识库 / Presales Fieldbook / 售前下一问」等旧身份表述，身份为 AI 学习库，字段为学习者视角
- **Pass Condition**：生产构建的全部中文路由 HTML 中旧身份词为 0（叙事性「客户场景」除外，白名单在任务中登记）
- **Evidence**：渲染测试 + 关键词扫描 + 浏览器抽查

### AC-2：知识内容零丢失
- **Type** `rule`
- **Pass Condition**：问答总数 = 396、稳定问答 ID 集合不变、模块数 = 27；每道问答的证据 sourceId 仍可解析
- **Evidence**：内容契约测试、question-overlap、来源解析检查

### AC-3：高时效知识复核闭环
- **Type** `rule`
- **Pass Condition**：模型目录/视频/协议/推理四类对象的关键可变事实全部对照一手来源复核；发现项有修正记录，相关来源 `verifiedAt` 与模块 `updatedAt` 同步；`sources:report` 保持 0 过期
- **Evidence**：复核清单（模块×事实×来源×结果）、git diff、sources:report

### AC-4：模块页标题语义归位
- **Type** `rule`
- **Pass Condition**：27 个模块页 H1 的第一文本为完整中文模块名，缩写与英文名为副级；不再出现「缩写巨型 H1 + 全名 small」结构
- **Evidence**：渲染测试断言 H1 结构 + 浏览器抽查

### AC-5：CSS 显著精简且视觉无回归
- **Type** `rule`
- **Pass Condition**：全站 CSS 总行数较基线（14,260 行，12 个文件去重）减少 ≥ 35%（即 ≤ 9,269 行），其中 fieldbook-v3.css 较 8,771 减少 ≥ 40%（即 ≤ 5,263 行）；除 AC-4 与首屏有意修改外，关键页面在 1440 / 1024 / 390 宽度下渲染结构与基线一致（人工比对）
- **Evidence**：行数统计、死代码引用分析、Chrome 截图比对

### AC-6：门禁与可访问性不破
- **Type** `rule`
- **Pass Condition**：`npm run check` 通过（lint/typecheck/单测/双语结构/build/bundle/渲染设计检查）；无脚本 SSR 正文可读；无控制台错误与全局横向溢出
- **Evidence**：check 输出、SSR 回归、浏览器检查

### AC-7：可读性与信息层级
- **Type** `rubric`
- **Dimension**：读者能否快速建立「这是什么 → 机制 → 边界 → 判断」的阅读路径
- **Scale** 1–5
- **Anchors**：1 = 封面化、首屏无真实知识、层级混乱；3 = 可读但层级平淡；5 = 首屏即可学习，层级清晰、重点边界突出
- **Pass Threshold** ≥ 4
- **Evidence**：真实页面人工评审（1440/1024/390）

### AC-8：知识密度
- **Type** `rubric`
- **Dimension**：单位版面承载的有效概念、机制、边界与可操作判断量
- **Scale** 1–5
- **Anchors**：1 = 大量空话/装饰；3 = 密度中等；5 = 每屏均有不可替代的知识点
- **Pass Threshold** ≥ 4，且不低于本轮基线水平
- **Evidence**：改造前后同屏内容要点对比 + 人工评审

### AC-9：去 AI 腔与实用性
- **Type** `rubric`
- **Dimension**：语言具体自然（无套路、无口号）+ 内容可直接用于自测与实战（追问、产物、通过标准）
- **Scale** 1–5
- **Anchors**：1 = 满篇正确的废话与套路句式；3 = 基本自然但偶有空话；5 = 像有经验的工程师写给自己的笔记，判断与边界具体
- **Pass Threshold** ≥ 4
- **Evidence**：逐段朗读式人工评审 + 代表页抽样
